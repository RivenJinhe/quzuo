# 去做 · 阿里云部署说明（2026-11-23）

## 一、为什么选轻量应用服务器

| 方案 | 能否跑本项目 | 结论 |
|---|---|---|
| 轻量应用服务器（Linux + Docker） | 能，预装 Docker 镜像 | **推荐**，学生券可覆盖 |
| ECS 云服务器 | 能 | 同轻量，配置更啰嗦，价格略高 |
| 函数计算 FC | 需改造入口、有执行时长与冷启动问题 | 不推荐，省不了钱 |
| OSS / 静态托管 | 只能放静态文件，跑不了 FastAPI+Postgres | 不可用 |

阿里云高校计划（云工开物）：学生认证通过后，**每人每 12 个月可领 300 元优惠券**，有效期 1 年，可抵扣轻量应用服务器等公共云产品。2 核 2G 轻量实例包年通常在 100–200 元区间，券基本能覆盖。

## 二、买之前先确认三件事

1. **实名认证**：阿里云必须实名，个人身份证即可。
2. **学生认证**：学信网在线验证，几分钟出结果；认证通过后到「云工开物」页领券。
3. **地域**：选离你近的（杭州/上海/北京），不要选海外，否则访问慢且可能触发风控。

## 三、购买与开放端口

1. 控制台 → 轻量应用服务器 → 创建。
2. 镜像：选 **Docker 基础镜像**（或 Ubuntu 22.04 + 自行装 Docker）。
3. 套餐：2 核 2G、系统盘 40–60G、带宽 3–5Mbps 足够。
4. 创建后在「防火墙」里**添加规则：TCP 8010，来源 0.0.0.0/0**。
5. 记下公网 IP。

> 为什么是 8010 而不是 80：中国大陆服务器绑域名走 80/443 必须 ICP 备案。用**纯 IP + 8010 端口**可以合法访问、不备案。缺点是没有 https、地址不好看。

## 四、上传代码

方式 A：在本机构建前端并上传部署包。安装 Node.js 24 和项目指定版本的 pnpm，然后在仓库根目录运行：

```bash
bash 脚本/打包部署包.sh
scp 交付物/<刚生成的部署包文件名> root@<公网IP>:/root/quzuo.tar.gz
```

```bash
# 服务器上
mkdir -p /opt/quzuo && tar -xzf /root/quzuo.tar.gz --strip-components=1 -C /opt/quzuo && cd /opt/quzuo
```

打包脚本会附上仓库根目录已有的 `.env.prod` 和 `.env`，请按部署凭据保管归档。

方式 B：服务器直接 `git clone`。仓库 Dockerfile 会使用 pnpm 构建前端。

## 五、配置并启动

```bash
cd /opt/quzuo
test -f .env.prod || cp .env.prod.example .env.prod
# 编辑 .env.prod：填三家 key；把 PG_PASSWORD 逻辑也改强密码（见 compose 注释）
vi .env.prod

# 强密码示例：同时改 compose 里的默认值或导出环境变量
export PG_PASSWORD='改成一段长随机串'
docker compose up -d --build
docker compose logs -f app
```

看到 `Application startup complete` 后访问：

```
http://<公网IP>:8010/app/
```

首页会重定向到 `/app/`。FastAPI 从 `web/dist/` 提供前端页面，前后端共用同一个来源和会话 Cookie。

## 六、两个必踩的坑

1. **`QU_COOKIE_SECURE` 必须 false**。用 `http://IP:8010` 访问时若为 true，浏览器会拒绝保存会话 cookie，表现是「登录成功但刷新就掉登录」。
2. **`QU_DATABASE_URL` 不要照抄 Neon 的**。本 compose 用容器内 Postgres，app 的环境变量已在 compose 里覆盖指向 `db:5432`；如果要用 Neon，把 QU_DATABASE_URL 写进 .env.prod，并删掉 compose 里 app 那行覆盖 + db 服务。

## 七、安全（公网必读）

后端已改为**必须注册才能使用**：未登录访问任何业务接口一律返回 401 `UNAUTHENTICATED`，数据按账号隔离。注册入口本身是开放的，上线后仍建议挡一道：

- 在 nginx 或安全组白名单限制访问 IP；
- 或给整个站点加 Basic Auth（nginx 一行配置 + htpasswd）；
- 或临时把 `QU_LLM_ALLOW_REAL` 设为 false 给别人看界面；
- 或在前端/nginx 加邀请码门槛（后端没有邀请码字段，需要额外加）。

## 八、日常运维

```bash
docker compose ps                 # 状态
docker compose logs -f app        # 日志
docker compose restart app        # 重启
docker compose down && docker compose up -d   # 重建（数据卷 pgdata 保留）
```

数据库备份：

```bash
docker compose exec db pg_dump -U qu qu_dev > /root/qu_backup_$(date +%F).sql
```
