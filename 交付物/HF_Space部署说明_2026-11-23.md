# 去做 · 部署到 Hugging Face Spaces（免费方案）

> 目标：把后端 + 前端挂到公网，团队同学打开链接就能用。
> 代价：0 元。HF Space 免费提供 2 vCPU / 16 GB 内存，域名固定，不用买。
> 代价二：48 小时没人访问会休眠，第一次打开要等 30–60 秒唤醒。

## 整体架构

```
浏览器  ──HTTPS──▶  Hugging Face Space（Docker 容器）
                      │  uvicorn + FastAPI + /app 静态前端
                      ▼
                    Neon（云端 PostgreSQL，免费 0.5 GB）
```

一条链接同时是前端和后端：`https://<你的用户名>-<space名>.hf.space`
（镜像构建时由 pnpm 和 Vite 生成页面，后端把 `web/dist/` 挂到 `/app`。）

## 准备（都免费，各 2 分钟）

1. **Hugging Face 账号** —— https://huggingface.co/join
2. **Neon 账号** —— https://console.neon.tech/signup （用 GitHub 登录最快）

---

## 第一步：在 Neon 建数据库

1. 登录 Neon → 新建项目，名字随便填（如 `quzuo`）
2. 项目建好后，首页会显示 **Connection string**，形如：

   ```
   postgresql://用户名:密码@ep-xxx-xxx.ap-southeast-1.aws.neon.tech/neondb?sslmode=require
   ```

3. **把它改一下**：在 `postgresql` 后面加上 `+psycopg`，最终要长这样：

   ```
   postgresql+psycopg://用户名:密码@ep-xxx-xxx.ap-southeast-1.aws.neon.tech/neondb?sslmode=require
   ```

   > 为什么要改：后端用的 SQLAlchemy 驱动名是 `postgresql+psycopg`，Neon 默认给的是 `postgresql`。

4. 把这条连接串存下来，下一步要用。

> 表结构不用手动建。后端启动时会自动执行 `Base.metadata.create_all`。

---

## 第二步：在 HF 建 Space

1. 打开 https://huggingface.co/new-space
2. 填写：
   - **Space name**：`quzuo`（决定域名，之后是 `https://<你的用户名>-quzuo.hf.space`）
   - **License**：随便选
   - **SDK**：**Docker** ← 关键，不要选 Gradio / Streamlit
   - **Docker template**：**Blank**
   - **Visibility**：**Public**（团队不用登录就能看；想私密就选 Private，但那样每个人都要有 HF 账号并加入）
3. 点 **Create Space**

创建后 HF 会自动生成一个 README 和 Dockerfile 模板——**不用管，下一步会从 GitHub 导入我们自己的**。

---

## 第三步：把代码接进来

有两个办法，任选其一。

### 办法 A：连 GitHub 仓库（推荐，以后改代码自动重新构建）

1. Space 页面 → **Settings** → **Repository** 区域
2. 找到 **"Connected repository"** / **"Link a GitHub repository"**
3. 首次会要求授权 HF 访问你的 GitHub，按提示授权
4. 选择仓库：`chuanyan0030/quzuo`，分支 `main`
5. 保存后 HF 会自动拉取并开始构建

> 前提：GitHub 仓库里已经有 `Dockerfile` 和根 `README.md` 的 frontmatter（这两样我已经加好了，push 上去即可）。

### 办法 B：直接上传文件（不想连 GitHub 时用）

Space 页面 → **Files** → **Add file** → **Upload files**，需要上传：

- `Dockerfile`
- `README.md`（带 frontmatter 的那个）
- `.dockerignore`
- `后端/requirements.txt`
- `后端/app/`（整个目录）
- `前端/` 下的两个 HTML 入口、`src/`、`package.json`、`pnpm-lock.yaml`、`tsconfig.json` 和 `vite.config.ts`

> 中文目录名上传后可能被转义，**优先用办法 A**。

## 第四步：填环境变量（关键，不填跑不起来）

Space 页面 → **Settings** → **Variables and secrets**。

**Secrets（加密，填 API Key）**：

| Name | Value |
|---|---|
| `QU_DATABASE_URL` | 第一步改好的 Neon 连接串 |
| `QU_PROVIDER_DEEPSEEK_KEY` | DeepSeek API Key |
| `QU_PROVIDER_KIMI_KEY` | Kimi API Key（可选） |
| `QU_PROVIDER_QWEN_KEY` | 通义 API Key（可选） |
| `QU_PROVIDER_MINIMAX_KEY` | MiniMax API Key（可选） |

**Variables（明文，普通配置）**：

| Name | Value | 说明 |
|---|---|---|
| `QU_LLM_ALLOW_REAL` | `true` | 不设就只走 stub，不调真模型 |
| `QU_LLM_DEFAULT_MODEL` | `deepseek/deepseek-chat` | 默认模型 |
| `QU_LLM_TIMEOUT_SECONDS` | `180` | 生成超时 |
| `QU_COOKIE_SECURE` | `true` | **HF 是 HTTPS，必须 true**，否则 Cookie 种不上 |
| `QU_TRIAL_TTL_DAYS` | `30` | 匿名试用地 |
| `QU_GEN_RATE_PER_MINUTE` | `6` | 每人每分钟生成上限 |

> 改完环境变量，Space 会自动重启一次（约 30 秒）。

---

## 第五步：等构建、验收到能用

1. Space 页面顶部有 **Building / Running** 状态条
2. 第一次构建要装 pymupdf 等依赖，**大约 3–5 分钟**
3. 变成 **Running** 后，打开：

   ```
   https://<用户名>-quzuo.hf.space/app/
   ```

4. 自检：
   - `/health` 应返回 `{"ok":true,...}`
   - `/api/v1/models` 里 `available` 为 `true` 的模型就是配好 key 的
   - 页面能打开、能建材料、能生成 → 成功

## 必须知道的坑

### 1. 地址一公开 = LLM Key 被人白嫖

后端给**匿名访客开 30 天试用身份**。Public Space 意味着任何人打开链接都能用你的 key 调模型。

三个措施，至少做第一个：

- **加访问口令**（推荐）：需要改一行后端代码，加一个环境变量 `QU_ACCESS_CODE`，没带口令的请求一律 403。需要我改就说一声。
- **Space 设成 Private**：只有你邀请的 HF 账号能访问，团队每人要注册 HF。
- **接受风险**：设小 `QU_GEN_RATE_PER_MINUTE`，当消耗品用。

### 2. 48 小时休眠

免费 Space 连续 48 小时没人访问会休眠，下次打开要等 30–60 秒冷启动。想让它在演示时保持唤醒，可以挂个定时 ping（比如 UptimeRobot 免费版每 5 分钟访问一次 `/health`）。

### 3. 上传的文件不持久

HF Space 的容器文件系统是临时的，重启就清空。本项目上传 PDF 是「转成 Markdown 立刻用，不落库」，所以不受影响；但**如果以后加了「原文件留存」功能，必须改存对象存储**（HF 提供付费持久化，或接 S3 兼容存储）。

### 4. 免费额度

Free Space：2 vCPU / 16 GB 内存，不限调用次数，不限时长。生成任务是等 LLM 返回，CPU 基本空转，不会撞上限。**唯一限制是休眠**。

### 5. 国内访问速度

hf.space 国内直连一般能打开，偶尔慢。演示前建议自己先开一次唤醒。
