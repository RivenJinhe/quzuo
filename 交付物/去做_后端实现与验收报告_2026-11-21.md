## 1. 结论

- 首版 PO 六步流程（存材料 → 检索确认 → 生成方案 → 同对话改条件 → 保存 → 回看/复制/看出处）已端到端跑通。

- 前端测试台可用（`/app/`），支持材料增删改查与搜索、文件上传转 Markdown、多模型勾选对比、结果卡与出处展开、方案保存/复制。

## 4. 六步流程的实现落点

| PRD 步骤 | 接口 | 关键实现 |
| --- | --- | --- |
| S1 存材料 | `POST /materials`、`POST /materials/extract` | 摘录 ≤20000 字；来源三态（citable/link_only/unusable）；上传文件先转 Markdown |
| S2 检索确认 | `POST /conversations`、`GET /retrieve`、`POST /materials/confirm` | 打分 = 命中×2 + 主题×3 + 可引用加权；只有链接的材料进候选但不许作结论 |
| S3 生成 | `POST /conversations/{id}/generations`（202）+ 轮询 | 入参白名单；关闭联网；出处快照落库 |
| S4 改条件（表单） | `PATCH /conversations/{id}/conditions` | version 乐观锁，同时把该对话 pending/running 生成置 superseded |
| S4 改条件（自然语言追问） | `POST /conversations/{id}/turns` | 一句话解析成条件增量 → version+1 → 作废旧生成 → 当场重排；解析器不调模型（`app/services/turns.py`，12 例单测） |
| S5 保存 | `POST /plans` | 同 owner+conversation UPSERT；只接受 succeeded 且版本最新的生成，否则 409 STALE_GENERATION |
| S6 回看/复制/出处 | `GET /plans`、`POST /plans/{id}/copy`、`GET /citations/{cid}` | 复制剥私人备注与选择理由；出处返回摘录快照 + 文件/页码 + jump_url |

## 5. 程序侧八项复核

模型输出只是候选，最终以程序计算为准：STRUCTURE、CITATION_GATE、NUMBER_WHITELIST、DURATION_TOTAL、RETAINED_COVERED、MATERIAL_DERIVE、BUDGET、TIMELINE。

- 阻断（block，不返回正文）：结构缺字段、引用全被剔除、必选项时长之和超过可用时长。
- 提示（notice，返回正文并标注）：总量超时、超预算、个别引用被剔除、数字不在白名单、用户要求保留的重点没出现。
- 自动改正（corrections）：物料数量随环节派生、时间线按到离推算重算。
- 所有复核结果写进 `generation.validation`，异常写 `generation_log`，便于验收对照。

### 5.1 三个验收用例的命中数字

| 用例 | 命中 |
| --- | --- |
| 复习（15 分钟→改 5 分钟） | DURATION_TOTAL total=5；旧生成保存被 409 拒；重复保存更新原记录 |
| 出行 | BUDGET per_person=95 vs 80，diff=15；DURATION_TOTAL total=30 vs 10；TIMELINE 15:30 到店 / 15:40 离开 / 15:55 返校 |
| 活动 | 2+12+8+3=25；题卡 20 与「猜词」绑定，删猜词后题卡同步删除；可用 10 分钟时 block，required=12、available=10、diff=2，放宽项 extra_minutes=2 |
| 自然语言追问 | 「时间只剩 5 分钟了」→ duration_minutes 15→5、DURATION_TOTAL total=5；「例题一定要讲」→ retained.must_keep_texts=["例题"]、RETAINED_COVERED covered=["例题"]；旧生成保存被 409 拒 |

## 6. 多模型对比

- `GET /api/v1/models` 给前端模型清单（不含密钥）；生成接口收 `model_ids`，每个模型一条 Generation，各跑一遍复核。
- 默认模型走 `.env` 的 `QU_LLM_DEFAULT_MODEL`；对比上限 `QU_LLM_MAX_COMPARE`（默认 4）。
- 实测：四家同题（15 分钟复习、课件第 8-12 页）均 succeeded、各 3 条 items、复核全过；`/models` 与 `/openapi.json` 中搜不到任何 `sk-` 字样。
- Kimi 温度必须为 1（其它值返回 400），已在 provider 内区分；MiniMax 走 `chatcompletion_v2` 并读 `base_resp.status_code`。

## 7. 账号与试用期

- 游客：`qu_trial` cookie（库内只存 sha256），30 天可写 + 7 天只读，37 天后 403。
- 注册即把当前游客数据绑定账号；登录生成独立 AuthToken，多设备共存，有效期 100 年。
- 所有资源按 `owner_id` 隔离，跨身份访问统一 404。

## 8. 上传文件 → Markdown

- `POST /api/v1/materials/extract`：pdf（pymupdf4llm，识别标题与表格）、docx（标题层级/列表/表格）、pptx（按页）、txt/md/csv；≤20MB、≤300 页、正文 ≤20000 字。
- 多页时每页加 `<!-- page N -->` 标记，出处页码可回溯。
- 引用闸门对材料与引用同时做 Markdown 归一化（剥 `# | ** <br> <!-- page N -->`），避免把模型正常引用误判为「不在原文里」。
- 不做 OCR 与版式还原；图片型文件提示「没有可提取的文字」。

## 11. 已知限制

- `/internal/dev/*` 三个调试端点无鉴权，上线前删除。
- 限流为单进程内存计数。
- 生成任务在进程内，API 重启会丢失进行中的生成。
- 前端是测试台，不是产品 UI；无移动端适配。
- 试用期只读期依赖数据库 `purge_at` 字段，没有后台清理任务。
