## 0. 怎么用这份文档

1. **开发自测**：按第三、四章逐条实现并勾选 BE 编号；每条都写了入参/出参/错误码，不需要再问。
2. **联调**：第三章每个接口都有典型请求与响应示例，前端可直接照着写。
3. **验收**：只跑第五章 AC-001 ~ AC-006。三条功能用例对应 PRD 4.3 三件事，三条非功能用例对应 PRD 6.1/6.3。
4. **边界争议**：第一章已经写明做什么、不做什么、降级长什么样；第六章把所有还没定死的地方列出来，每条给了建议结论，不静默假设。

术语约定：

- **材料**＝个人知识库里的一条记录（摘录/链接）；**方案**＝一次生成的结果，可保存为「已存方案」。
- **草稿**＝生成出来但未保存的结果（存在 generation 记录里）；**已存方案**＝plan 记录。
- 「本次」指当前对话的一次生成请求（一个 generation）。
- 时间统一按服务端 UTC 存储，方案内展示的时刻按 Asia/Shanghai 格式化。

- **BE-029** 每次生成只传本次选定材料、必要备注、用户条件，不传全量知识库、不传其他用户数据（见 BE-401）。

# 二、数据模型（字段级）

## 2.1 通用约定

**BE-101** 所有业务表遵循同一套约定，实现时按此打底。

| 约定 | 内容 |
| --- | --- |
| 主键 | id：uuid v4，文本存储，服务端生成 |
| 归属 | 除 trial_user 外，所有表必带 owner_id（= trial_user.id）；任何读写 SQL 必须带 owner_id = 当前身份，禁止只按 id 取 |
| 归属校验方式 | 单体资源：先按 (id, owner_id) 查，查不到统一返回 404 NOT_FOUND；列表：owner_id 强制注入，不接受客户端传 owner_id |
| 时间 | created_at / updated_at 为 timestamptz，UTC 存；展示层转 Asia/Shanghai |
| 删除 | 业务上删除 = 软删（deleted_at 置为当前时间）；所有查询默认过滤 deleted_at is null |
| 乐观锁 | 可编辑实体带 version（int，默认 1）；PATCH 带 If-Match 或期望 version，不匹配返回 409 VERSION_CONFLICT |
| 字符校验 | 文本先 trim；长度按 Unicode 码点数计；拒绝控制字符 |
| 枚举 | 用字符串枚举落库，未知值一律 400 VALIDATION_ERROR |

## 2.2 试用者（trial_user）

### BE-102 身份与有效期的技术结论

- **身份载体**：服务端下发匿名 Cookie，名字 qu_trial，值为 32 字节随机数的 base64url（44 字符）；HttpOnly、Secure、SameSite=Lax、Path=/。库里只存 sha256(token)，不存明文。
- **为什么不用浏览器指纹**：指纹在手机浏览器上不稳定，且会造成「同一台机器换隐私窗口仍能读到别人材料」的串号风险，与 PRD 6.1「每个人只可读写自己的」冲突。所以用 Cookie token，并明确接受「清 Cookie 即丢身份」的代价。
- **有效期结论**：**30 天，自首次访问起算，固定不滑动**。理由：滑动续期会让「30 天」在验收时没有确定口径；固定天数可以用一条 SQL 验完（expires_at = created_at + 30d）。
- **过期后的行为**（三段式，可直接测）：
  - 第 0 ~ 30 天：status = active，读写全放开。
  - 第 30 ~ 37 天：status = readonly，GET 类接口 200；任何写接口（POST/PATCH/DELETE，含生成与保存）返回 403 TRIAL_EXPIRED_READONLY，message「试用已到期，你仍可查看和复制已存方案，但不能新增或修改」。
  - 第 37 天起：status = expired，所有接口 403 TRIAL_EXPIRED；数据保留到第 67 天，之后物理清除（此项由开发组按实际数据库能力执行，不影响本期验收）。
- **配置项**：TRIAL_TTL_DAYS（默认 30）、TRIAL_READONLY_DAYS（默认 7），验收环境用默认值。
- **测试后门**：仅 dev 环境开放 POST /internal/dev/trials/{id}/expire?days=N，用于把某个身份的过期时间调到 N 天后，供 AC-004 / 过期用例使用；生产环境该路由必须 404。

**BE-121 搜索索引策略**：首版单用户材料量预期 < 200 条，按 (owner_id, topic) 与 (owner_id, updated_at desc) 建普通索引即可，关键词搜索用 ILIKE 全表扫；若压测发现慢，再加 pg_trgm GIN 索引于 lower(title || excerpt || note)，不改接口。

**BE-122 不变式**：
1. content_status = quotable 的材料，excerpt 一定非空且 ≥ 20 码点；任意 PATCH 若把 excerpt 清空，必须同时把 content_status 降为 link_only，否则 400。
2. source_type = web_link 与 courseware 的来源字段互斥：web_link 不得带 source_page_start / source_page_end，courseware 不得带 source_url。
3. 材料被引用后删除（软删）不影响已存方案的引用快照（快照见 BE-160）；已存方案打开时引用仍可展开，标注「原材料已删除」。

| trip | party_size | int 1 ~ 200 | 是 | 人数 |
| trip | depart_at | string(HH:MM) | 是 | 出发/离馆时刻（用例：15:15） |
| trip | back_by | string(HH:MM) | 是 | 硬性返校/返回时刻（用例：15:55） |
| trip | budget_per_person | number ≥ 0 | 否 | 人均预算（用例：80）；缺省则不校验费用，全部花费标待确认 |
| trip | legs | array[{from, to, minutes}] | 是 | 路段耗时，minutes 为 int 1 ~ 600，用户填（不查地图） |
| trip | cost_items | array[{label, amount, status(known, unknown)}] | 否 | 已知花费项；status = unknown 的金额不参与加总 |
| trip | wanted | array[{label, minutes}] | 否 | 想要的停留（用例：咖啡馆 30 分钟） |
| event | party_size | int 1 ~ 200 | 是 | 人数（用例：20） |
| event | total_duration_min | int 1 ~ 600 | 是 | 本次总时长（用例：25 / 改成 10） |
| event | fixed_furniture | bool | 否 | true 表示桌椅固定，换座游戏必须排除（用例：true） |
| event | must_keep | array[{name, minutes}] | 否 | 必须保留的环节（用例：同桌互访 12 分钟） |
| event | excluded | string[] | 否 | 用户明确排除的玩法（用例：换座类） |

**BE-132 retained 结构**

json 示例（文字描述）：key_points 为数组，每项含 text、material_id（可空）、pending_confirmation（bool）；schedule 为数组，每项含 name、minutes；notes 为数组，每项为字符串。retained 只由两个来源写入：用户点「这个保留」或条件里出现 must_keep 且已生成过一轮。生成时 retained 必须原样出现在入参与方案中，模型不得删除。

**BE-133 状态机（只允许这些迁移）**

collecting → materials_proposed（调检索）→ materials_confirmed（确认材料）→ generating（发生成）→ draft_ready（成功）/ failed（失败）；draft_ready 或 failed 都可以回到 generating（改条件后重新生成）；任何状态可被新一次 conditions 变更打回 materials_confirmed 之前的语义不变，但 version 必须 +1。

**BE-134 旧结果丢弃的落库实现**：generation 表存 conversation_version（发起时快照）。判活规则：generation.conversation_version 与 conversation.version 相等才可写入 draft_ready；不等则写 superseded 并丢弃 result。这样即使旧请求晚到、甚至服务重启，也不会覆盖新一轮。

## 3.1 通用约定

**BE-200** 所有接口遵循以下约定。

| 项 | 约定 |
| --- | --- |
| 基础路径 | /api/v1 |
| 协议 | HTTPS；请求与响应 application/json; charset=utf-8；时间用 ISO8601（UTC，带 Z 或偏移） |
| 鉴权 | 每个请求携带 Cookie qu_trial；服务端解析为 trial_user，写入请求上下文。无 Cookie 且非白名单接口 → 401；Cookie 无效 → 401 |
| 归属校验 | 所有查询强制 owner_id 过滤；单体资源按 (id, owner_id) 查，查不到 404（不区分「不存在」与「不是你的」） |
| 请求 id | 响应体顶层带 request_id，用于排查；错误响应必带 |
| 幂等 | 创建类 POST 接受 Idempotency-Key 头（值由前端生成 UUID），同 key + 同路径 + 同 body 在 10 分钟内返回首次结果；保存用 UPSERT；材料选择用 PUT 全量替换 |
| 分页 | 游标分页：limit（默认 20，最大 100）+ cursor（上一页返回的 next_cursor）；响应带 has_more |
| 版本 | 可编辑实体带 version；PATCH 需带 expected_version，不匹配 409 VERSION_CONFLICT，响应带当前 version 与最新数据摘要 |
| 错误体 | 统一 { code, message, request_id, field, details }；message 直接给用户看的中文 |
| 限流 | 单身份生成 ≤ 6 次/分钟、其他写 ≤ 60 次/分钟，超限 429 RATE_LIMITED，响应带 retry_after_seconds |

**BE-208 错误码表（全量，前端按 code 分支，不按 message 判断）**

| HTTP | code | 触发场景 | 用户可见文案（示例） |
| --- | --- | --- | --- |
| 400 | VALIDATION_ERROR | 字段缺失/类型错/超长/枚举非法/conditions schema 不符 | 「总时长需要填 1 到 600 之间的整数」 |

  }

~~~

### BE-231 重新检索（换关键词/重跑）

- **接口**：POST /api/v1/conversations/{cid}/retrieve
- **入参**：{ query_hint: string（可空，用户补充的关键词）, expected_version: int }
- **出参**：同 BE-230 的 proposed / withheld 部分（不含 conversation 基本信息）。
- **幂等**：不幂等（每次重跑可不同），但不得修改 material_ids（未确认前不改用户的选择）。
- **错误码**：400、401、403、404、409。

### BE-232 确认采用哪些材料

- **接口**：PUT /api/v1/conversations/{cid}/materials/confirm
- **入参**：{ material_ids: uuid[], expected_version: int }（用户增减后的最终清单）
- **校验**：与 BE-215 相同；额外把 withheld 里被选中的 link_only 材料剔除并在响应说明（BE-441），若最终为空 → 412 SOURCE_INSUFFICIENT。
- **出参 200**：{ conversation_id, material_ids, excluded: [{ material_id, reason }], version, status: materials_confirmed }

### BE-233 对话内改条件（含「保留已确认项」）

- **接口**：PATCH /api/v1/conversations/{cid}/conditions
- **入参**：

| 字段 | 类型 | 必填 | 说明 |
| --- | --- | --- | --- |
| conditions | object | 是 | 部分更新即合并（PATCH 语义），按 task_type schema 校验合并后的整体 |
| retained_add | array | 否 | 用户新确认要保留的重点/安排，追加进 retained |
| note | string | 否 | 覆盖本次备注（留空串表示清空） |
| expected_version | int | 是 | 乐观锁 |

- **行为**：version + 1；retained 中已有条目**不得被覆盖或删除**（只能追加）；若仍在 generating，本接口先取消旧生成（旧 generation 置 superseded），保证「以最后一次输入为准」。
- **出参 200**：{ conversation_id, version, conditions, retained, cancelled_generation_id }
- **错误码**：400、401、403、404、409。
- **示例请求**：

~~~json
{ "conditions": { "total_duration_min": 5 }, "retained_add": [], "expected_version": 3 }
~~~

### BE-234 生成方案（异步，返回 generation_id）

- **接口**：POST /api/v1/conversations/{cid}/generations
- **入参**：{ expected_version: int, note: string 可空, conditions: object 可空（等价于先 PATCH 再生成） }
- **鉴权/归属**：Cookie + 对话归属。
- **幂等**：以 (conversation_id, expected_version) 为幂等键；同组合重复提交返回同一个 generation_id（200，不再新建）。
- **前置校验（同步返回，不排队）**：material_ids 非空且全部可引用（否则 412 / 剔除说明）；conditions 满足必填；否则 400。
- **出参 202**：{ generation_id, status: "queued", poll_after_ms: 1000, timeout_after_ms: 60000 }
- **错误码**：400、401、403、404、409（版本冲突）、412、429。

### BE-235 轮询生成结果

- **接口**：GET /api/v1/generations/{gid}
- **出参 200**：

| 字段 | 说明 |
| --- | --- |
| status | queued / running / succeeded / failed / superseded / timeout |
| result | succeeded 时给出：body_public（Markdown 正文）、body_private_note、rationale、citations[{ seq, material_id, excerpt, file_name, page, url, pending_confirmation }]、structured{ segments, costs, timeline, material_list, unknowns } |
| validation | 第四章各项复核结果：{ duration_sum, cost_sum, material_sync, timeline, citation_gate, grounding }，每项含 pass、值、差额 |
| pending_items | 被标「待确认」的条目（含原因：页码待补 / 价格未知 / 路程未知） |
| error | failed / timeout 时给 code + message（用户可直接展示） |

- **判活**：若 conversation.version 已大于本 generation 的 conversation_version，返回 status = superseded（且不再返回 result）。
- **错误码**：401、403、404。

**BE-236 为什么用异步 + 轮询**：改条件并发（BE-233 取消旧请求）、60 秒超时、断网后重试都需要一个可被外部取消/丢弃的句柄；同步接口在断网时无法区分「还在算」和「已经算完但没收到」，会让 AC-005（异常恢复）无法验收。轮询间隔 1 秒，前端最长等 90 秒。

### BE-237 取消生成（可选实现，但接口必须在）

- **接口**：POST /api/v1/generations/{gid}/cancel
- **行为**：置 superseded 并 AbortController 中止上游请求；丢弃一切后续返回。
- **出参 200**：{ generation_id, status: "superseded" }；已成功的不受影响（返回 409）。

# 四、生成链路与校验规则（半验收核心）

## 4.1 调模型时到底传什么

**BE-401 入参白名单（只允许这些字段进 prompt，多一个都不行）**

| 允许 | 内容 | 上限 |
| --- | --- | --- |
| goal | 用户原话 | 500 码点 |
| task_type | review / trip / event | — |
| materials[{id, title, topic, excerpt, note, source_label, page}] | 本次选定且 content_status = quotable 的材料 | ≤ 20 条，摘录合计 ≤ 12000 码点 |
| conditions | 本次条件（按 task_type schema） | ≤ 3000 码点 |
| retained | 用户已确认的重点/安排 | ≤ 2000 码点 |
| pending_facts | 上一轮被标「待确认」的条目（仅用于让模型别重复猜） | ≤ 1000 码点 |

**禁止入参**：全量知识库、未选中的材料、其他试用者的任何数据、Cookie/token、材料 id 之外的内部主键、服务端日志、模型密钥以外的一切密钥。

**BE-402 关闭联网**：调用上游时不开任何检索/浏览器/工具能力（tools 字段为空或直接不传）；若上游默认带联网，必须显式关闭并在 generation_log 记录 web_search = false。验收方式：用材料里没有的问题（如「学校旁边那家新开的店多少钱」）生成，结果必须是「待确认/缺材料」，不得出现具体价格。

**BE-403 密钥与传输**：模型密钥只存在服务端环境变量，任何接口响应、日志、错误信息都不得回显；线上必须 HTTPS；Cookie 带 Secure。

**BE-404 超时与重试**：单次上游调用超时 50 秒，程序总预算 60 秒；超时置 generation.status = timeout 并返回用户可读文案。上游 5xx 自动重试 1 次（同一请求，不重算参数）；不重试 4xx。

**BE-405 费用与耗时记录**：每次生成落 generation_log：model、latency_ms、tokens_in、tokens_out、cost_estimate（按单价换算，单价写配置）。验收时能回答「这一份方案花了多少、等了几秒」（PRD 7.3）。

**BE-406 提示词骨架（后端内置，前端不可改）**：系统段声明「只能用给定材料摘录与给定条件；材料未覆盖的一律输出待确认，不得引入外部知识」；然后按 task_type 给各自的输出 schema；最后要求输出逐条 citations 与 grounding 字段。三个任务共用同一骨架，只换 schema 与输出格式说明。

**BE-407 结构化输出**：上游必须返回 JSON（走 response_format 或严格解析 + 一次修复重试）。解析失败 → generation failed（code MODEL_OUTPUT_INVALID），不把半成品给用户。

**BE-408 同一对话的上下文**：只传最新一轮的 conditions + retained + 材料，不把历史轮次的全文方案再塞回去（省 token，也避免旧结论污染）；历史保留项由 retained 承载。

## 4.2 程序侧复核（不依赖模型自觉）

**统一约定**：复核在写 generation.result 之前跑；每项都写进 validation，结构为 { pass: bool, value: any, required: any, diff: any, conflict_level: none/notice/block, message: string }。冲突分级见 BE-419。

**BE-420 复核一：时长加总**

| 项 | 内容 |
| --- | --- |
| 输入 | structured.segments[{ name, minutes }]；conditions.total_duration_min；conditions.must_keep[{ name, minutes }] |
| 算法 | 1) 每段 minutes 必须为 ≥1 的整数，否则该项 fail；2) sum = 各段之和；3) sum 必须等于 total_duration_min；4) must_keep 中每个 name 必须能在 segments 找到对应段，且该段 minutes ≥ must_keep.minutes（不允许悄悄压缩用户要保留的时长） |
| 失败文案 | 「方案内各段时长合计 S 分钟，与本次可用 T 分钟不一致（差 D 分钟）。可以：删除「X」（M 分钟）/ 把总时长放宽到 S 分钟 / 缩短「Y」。」 |
| 冲突分级 | Σ must_keep.minutes > total_duration_min → block；否则 notice |

**BE-421 复核二：费用加总与预算差额**

| 项 | 内容 |
| --- | --- |
| 输入 | conditions.cost_items[{ label, amount, status }]；conditions.budget_per_person；structured.costs[] |
| 算法 | 1) known = Σ amount（status = known）；2) unknown_count = status = unknown 的条数；3) diff = known − budget_per_person；4) diff > 0 → 记 COST_OVER_BUDGET，并从「已知费用项中 amount 最大、且不在 must_keep / 不在必到站」的项里挑一个作为可删建议；5) unknown_count > 0 时在结果上标「不含 N 项待确认」，但不算失败 |
| 失败文案 | 「人均已知花费 K 元，超出预算 B 元 D 元。可删减：咖啡馆（人均 30 元）。」 |
| 冲突分级 | 必选项费用之和 > budget → block；否则 notice |

**BE-422 复核三：物料数量随环节删减同步变化**

| 项 | 内容 |
| --- | --- |
| 输入 | structured.segments（环节清单）；conditions.party_size；内置派生规则表 |
| 派生规则表（首版硬编码，可配置） | 题卡 ← 存在名字含「猜词」的环节，数量 = party_size；名牌 ← 恒存在，数量 = party_size；桌椅 ← fixed_furniture = true 时数量 = party_size 且标「不可变」；其他自由物料不派生 |
| 算法 | 1) 由 segments 推导期望物料集合 E（key → qty）；2) 取模型输出 M；3) 对 E 中每项：M 缺该项或 qty 不等 → 以 E 为准覆盖，写 corrections[{ code: MATERIAL_SYNCED, key, model_qty, expected_qty, reason }]；4) 对 M 中不在 E 的自由物料：qty > party_size × 2 才置 notice，不覆盖 |
| 是否阻断 | 不阻断（确定性派生量以程序为准，直接覆盖并告知） |
| 用户文案 | 「已按环节同步物料清单：删去「猜词」，20 张题卡一并移除。」 |

**BE-423 复核四：时间线到离时刻可推算**

| 项 | 内容 |
| --- | --- |
| 输入 | conditions.depart_at、back_by、legs[{from,to,minutes}]、wanted[{label,minutes}]；structured.timeline 或 stops |
| 算法 | t0 = depart_at（HH:MM 解析为当分钟）；对每个节点 i：arrive_i = t_{i-1} + leg_{i-1}.minutes；available_i = next_leg_start_boundary − arrive_i（即必须离开以赶上 back_by）；stay_i = min(wanted_i, available_i)；leave_i = arrive_i + stay_i；最后一段之后 arrive_school = leave_last + leg_last.minutes，必须 ≤ back_by。每步都写回 timeline[{ name, arrive, leave, stay_min, available_min }] |
| 校验 | 1) 每个节点 arrive/leave 必须能由 depart_at 逐步推出（不许出现凭空时刻）；2) 任一节点 required > available → 记 TIME_WINDOW 并给差额；3) arrive_school > back_by → 记 HARDBOUND（block） |
| 失败文案 | 「咖啡馆最多可用 10 分钟，比想要的 30 分钟少 20 分钟。可以：删去咖啡馆 / 把返校时间放宽到 16:15 / 缩短前一段 20 分钟。」 |
| 冲突分级 | 该站属于 must_keep → block；否则 notice |

**BE-424 复核五：引用闸门（citation gate）**

- 每条结论必须带 material_id + excerpt + page（课件）或 url（链接）。
- 程序校验：excerpt 归一化后必须是被引材料 excerpt 的子串（归一化规则见 BE-448）；page 必须落在 [source_page_start, source_page_end] 区间内。
- 不通过 → 该条置 pending_confirmation = true，正文该处加「（待确认：材料未讲到这一点 / 页码待补）」，并进 pending_items；**不删除该条**（PRD 要求「标待确认」而不是静默删掉）。
- 一条都不过 → 视为材料不足，返回 412 SOURCE_INSUFFICIENT，附「请补充能支撑这些结论的原文」。

**BE-425 复核六：结构化字段完整性**

- review 必须有 segments + citations；trip 必须有 timeline + costs；event 必须有 segments + material_list。
- 缺 → 带缺失项修复一次（只重试一次）；仍缺 → generation failed（GENERATION_INCOMPLETE），不返回半成品。

**BE-426 复核七：数字白名单**

- 正文中出现的金额、分钟数、页码，必须能在 citations / conditions / computed（程序算出的派生量）三者之一找到同值；否则进 ungrounded_entities（BE-462）。
- 这条是「不得编造价格」的最后一道网：模型就算绕过 grounding 字段，凭空写的 128 元也过不了。

**BE-427 validation 完整结构**（一次生成必须写全）：

~~~json
{
  "duration_sum": { "pass": true, "value": 15, "required": 15, "diff": 0, "conflict_level": "none", "message": "" },
  "cost_sum":    { "pass": false, "value": 95, "required": 80, "diff": 15, "conflict_level": "notice", "message": "人均已知花费 95 元，超出预算 80 元 15 元。可删减：咖啡馆（人均 30 元）。" },
  "material_sync": { "pass": true, "value": [], "required": [], "diff": null, "conflict_level": "none", "message": "" },
  "timeline":    { "pass": false, "value": 10, "required": 30, "diff": 20, "conflict_level": "notice", "message": "咖啡馆最多可用 10 分钟…" },
  "citation_gate": { "pass": true, "value": { "total": 4, "passed": 4 }, "required": null, "diff": null, "conflict_level": "none", "message": "" },
  "grounding":   { "pass": true, "value": [], "required": [], "diff": null, "conflict_level": "none", "message": "" }
}
~~~

**BE-428 复核结果怎么用**：

- 所有项 pass 或仅 notice → generation.status = succeeded，正文正常返回，notice 项在正文对应位置带标记（如「（超出预算 15 元）」），并在 validation 与 conflicts[] 里留结构化数据。
- 任一项 conflict_level = block → generation.status = conflict，**不返回正文**，只返回 conflicts[] + relax_options[]（每项含 id、label、effect、改动后的 expected 值），前端展示成单选，用户选完走 BE-233 改条件再生成。
- 复核报告必须持久化；同一份方案二次保存时 validation 随 plan.structured 存快照。

**BE-419 冲突分级判定（程序级，不看模型怎么说）**

| 情形 | 分级 | 理由 |
| --- | --- | --- |
| Σ must_keep.minutes > total_duration_min | block | 用户要保留的东西放不进总时长，必须由用户取舍（AC-003 的 10 分钟用例） |
| 非 must_keep 段导致 sum ≠ total | notice | 可自动调整或建议删段 |
| 必选项费用之和 > 预算 | block | 不删必选项无解 |
| 已知总花费 > 预算 | notice | 有可删的站（AC-002 的 95 与 80） |
| wanted 时长 > available 且该站非 must_keep | notice | 可删站或放宽（AC-002 的咖啡馆） |
| 该站是 must_keep 且 available 不足 | block | 无解 |
| 返校/返回硬时刻无法满足 | block | 硬约束 |
| 页码缺失 / 材料未覆盖某结论 | notice（标待确认） | PRD 要求标待确认，不是失败 |
| 出现无出处地点/价格 | block（failed） | BE-462 |

## 4.3 材料不足与冲突的处理（逐条可验收）

**BE-440 总原则**：先报缺什么，再问要不要继续；不静默降级、不静默补写。

**BE-441 只有链接的材料**

- 判定：content_status = link_only（或 unavailable）。
- 处理：不进入 prompt；在 proposed 的 withheld_materials 里返回，reason = LINK_ONLY，hint「《标题》只有链接，请补充原文摘录后再用于生成」；用户在确认材料时若坚持选它，确认接口把它剔除并在 excluded 里说明；若剔除后清单为空 → 412 SOURCE_INSUFFICIENT，文案「选定的材料只有链接，请先补原文摘录」。
- 可验收点：生成请求的 request_snapshot.materials 中不出现 link_only 材料 id；方案 citation 中也不得出现该 material_id。

**BE-442 课件没讲过的结论**

- 判定：citation 校验（BE-424）不通过，即摘录不是材料原文子串、或页码不在材料页码区间、或材料没有页码。
- 处理：置 pending_confirmation，正文标「（待确认：页码待补）」或「（待确认：材料未讲到这一点）」，进 pending_items，message 给补录指引「请补充《讲义》中讲这一点的页码与原文」。
- 可验收点：pending_items 非空；正文含「待确认」字样；公开复制版是否保留该标记——保留（见 Q-004）。

**BE-443 价格/路程未知**

- 判定：conditions 里该字段缺失（budget 缺失、legs 缺一条、cost_items 有 status = unknown），或材料里没有对应数字。
- 处理：正文该处输出「待确认」而不是数字；该值不参与加总；加总结果附注「（不含 N 项待确认）」；进 unknowns[]。绝不查地图、绝不估价。
- 可验收点：用一份完全没提价格的行程生成，cost_sum.value 里不含任何推测数字，且 unknowns 里能看到缺哪项。

**BE-444 要求冲突**

- 处理：算出差额（分钟或元），返回 conflicts[{ code, station/segment, available, required, diff }] + relax_options[{ id, label, effect, patch }]。用户选一项后由 BE-233 改条件再来一轮。
- 禁止：自动替用户放宽、自动删掉 must_keep、把差额说成「大概够用」。
- 可验收点：AC-002 必须出现 available = 10、required = 30、diff = 20 与 COST_OVER_BUDGET diff = 15；AC-003 必须出现 required = 12、available = 10、diff = 2 且 status = conflict。

**BE-445 材料太少（< 1 条可引用）**

- 处理：不调模型（省费用，也避免模型拿空气编），直接 412，message「这次没有可用的材料，请先在收藏里补一条摘录」。可验收点：generation 不产生记录，generation_log 无新增。

**BE-446 材料与目标对不上**

- 处理：不阻断；但 proposed.reason 必须逐条写清为什么选它；生成后若所有 citation 都落在同一条材料上，响应里加 hint「这次只用到 1 条材料，可以再补几条」。可验收点：hint 出现条件可测。

**BE-447 材料被中途删除/编辑**

- 处理：生成用发起那一刻的快照（request_snapshot），不受后续编辑影响；引用快照同样独立。可验收点：保存方案后编辑材料，展开出处仍是旧摘录（BE-271）。

**BE-448 归一化规则（子串匹配要用，必须实现一致）**

1) 全角转半角（含数字、字母、标点）；2) 去掉所有空白字符（含全角空格、换行）；3) 统一中英文标点为对应集合；4) 英文小写化；5) 不做同义词替换、不做去停用词。归一化后再判子串包含，两边都归一化。

## 4.4 「不得编造外部地点、价格或课件结论」的拦截与记录

**BE-460 三类受控实体**

| 类型 | 定义 | 允许的来源 |
| --- | --- | --- |
| place（地点） | 任何具名地点/店名/场馆 | 材料摘录、conditions 里的 from/to、用户确认过的 pending_facts |
| price（价格/费用） | 任何金额数字（含人均、合计） | 材料摘录、conditions.cost_items、由程序按数量×单价算出的 computed |
| claim（课件结论） | 复述课件内容的一句话 | 必须带 citation（材料 id + 原文子串 + 页码） |

**BE-461 拦截方式（三段式）**

1. **入参约束**：prompt 明确「只能使用给定摘录与条件，材料没写的一律输出待确认」；附带 task_type 对应 schema 要求模型对每个 place/price 输出 grounding: { source: "material", material_id } 或 { source: "condition", key } 或 { source: "unknown" }。
2. **出参校验**：程序对每处 place/price/claim 校验 grounding 可解析、且能在对应材料/条件里找到匹配（地点做名称匹配，价格做数值匹配，结论走 BE-424 子串校验）；对不上的记 ungrounded_entities。
3. **拦截动作**（首版取严）：ungrounded_entities 非空 → 带一次修复重试（把违规项作为「不许这样写」反馈给模型）；仍非空 → generation.status = failed，code = UNGROUNDED_CONTENT，**不把正文给用户**，message「有 2 处内容在材料里找不到出处（{地点/价格}），请补充材料或改条件」。前端展示被点出的位置，用户可补材料后重试。

**BE-462 记录方式（可查、可复现）**

- 每次生成一行 generation_log：generation_id、prompt_hash（入参规范化后的 sha256）、material_ids、model、web_search = false、latency_ms、tokens、cost_estimate、citation_check{total, passed, failed_ids}、ungrounded_entities[{type, text, reason}]、corrections[]、unknowns[]、fail_code。
- 验收动作：拿任何一份方案，按 generation_id 查日志，必须能回答三个问题——用了哪几条材料、每条结论对应哪条摘录哪一页、有没有被程序纠正/拦下的地方。

**BE-463 为什么不做关键词黑名单**：地点与价格是开放集合（新店、新价格随时出现），黑名单只能拦住见过的，反而给出「已拦截」的错觉。所以一律走白名单（必须能指到材料或条件）+ 结构校验，宁可多报待确认。

**BE-464 提示词与温度**：temperature 取低值（≤0.3），同一输入重跑结果应基本稳定；提示词版本号写进 generation_log，便于回归对比。

**BE-465 越界时不得做的三件事**：不得把材料里没有的价格写成「约」、「左右」并给出数字；不得把别处的通用知识当成本次材料结论；不得在失败时返回「部分可用」的半截方案（要么有出处，要么明确待确认）。

**BE-466 与保存的关系**：status = failed 或 conflict 的 generation 不允许保存（409 STALE_GENERATION / 400），避免把冲突结论固化成已存方案。

| 物料 | material_list 不含题卡（或数量 = 0） |
| 纠正记录 | validation.material_sync 或 result.corrections 含 { code: MATERIAL_SYNCED, key: 题卡, model_qty: 20, expected_qty: 0 } |
| 用户文案 | 响应带「已按环节同步物料清单：删去「猜词」，20 张题卡一并移除。」 |

### S8 总时长缩到 10 分钟 → 阻断

PATCH conditions：total_duration_min = 10（must_keep 仍是互访 12 分钟）→ 重新生成。

| 断言目标 | 期望 |
| --- | --- |
| 生成状态 | status = conflict（不是 succeeded，也不返回正文） |
| 冲突登记 | conflicts[0] = { code: DURATION_MUST_KEEP, required: 12, available: 10, diff: 2 } |
| 文案 | 「仅同桌互访就需 12 分钟，比总时长 10 分钟多 2 分钟。」 |
| 放宽选项 | 含「把总时长放宽到 12 分钟」「把互访缩短到 10 分钟」「去掉保留要求」 |
| 正文 | result.body_public 不存在（不许返回半成品） |
| 保存 | POST /plans 用该 generation → 400 / 409，已存方案不变 |

**AC-003 通过判据**：25 分钟构成可核（2+12+8+3 或同等有效拆分）；删环节后物料同步；10 分钟时以「差 2 分钟」阻断而不是硬凑。

## AC-004 隔离：换一个试用身份读不到前一人

| 步骤 | 请求（身份 A 已建 2 条材料 + 1 份方案） | 期望（身份 B，另一 Cookie） |
| --- | --- | --- |
| S1 | GET /materials | 200；data = []（看不到 A 的材料） |
| S2 | GET /materials/{A 的 material_id} | 404 |
| S3 | PATCH /materials/{A 的 material_id} | 404 |
| S4 | DELETE /materials/{A 的 material_id} | 404（且 A 的数据未被删） |
| S5 | GET /plans | 200；data = [] |
| S6 | GET /plans/{A 的 plan_id} | 404 |
| S7 | POST /plans/{A 的 plan_id}/copy | 404 |
| S8 | GET /citations/{A 的 citation_id} | 404 |
| S9 | POST /conversations（material_ids 含 A 的 material_id） | 400，details 指出「材料不存在或不属于当前身份」 |
| S10 | 用 A 的 conversation_id 发 POST generations | 404 |

**判据**：B 的所有响应体与错误文案中不得出现 A 的任何 title 或摘录片段（用字符串包含断言）；A 侧数据在 B 操作后仍完整（重新用 A 的 Cookie 查，条数与内容不变）。另测过期：dev 接口把 A 的 expires_at 调到 31 天前 → A 的 GET 仍 200，写操作 403 TRIAL_EXPIRED_READONLY；调到 38 天前 → 全部 403 TRIAL_EXPIRED。

## AC-005 异常：断网 / 超时 / 复制失败

| 场景 | 操作 | 期望 |
| --- | --- | --- |
| 断网 | S6 发出后立即断网 10 秒再恢复 | 恢复后 GET /conversations/{cid}：material_ids、conditions、retained 与断网前逐字段一致；status 为 generating 或 draft_ready；重新 POST generations（同 expected_version）→ 200 返回同一 generation_id（幂等，不重复计费） |
| 生成超时 | dev 开关让上游延迟 55 秒 | GET /generations → status = timeout，error.code = GENERATION_TIMEOUT，message「生成超时，可以重试；已填的条件没有丢」；conversation.status = failed 但 conditions / material_ids / retained 全部保留；改为正常后重试 → succeeded |
| 保存中失败 | POST /plans 前断网 | 重发同请求 → 只产生一条 plan（UPSERT 幂等）；version 不跳号 |
| 复制失败 | 前端 clipboard 抛错 | POST /plans/{id}/copy 的响应里 text 为纯文本、≤ 20000 字符、不含 HTML 标签，fallback.selectable = true；前端用 text 渲染可手动选取区域（后端保证 text 与复制内容完全一致） |

**判据**：以上四场景下，任何失败路径都不得清空材料、条件或已存方案（每次失败后都用 GET 校验一遍）。

## AC-006 并发与时序：最后一次为准、重复保存更新原记录

| 场景 | 操作 | 期望 |
| --- | --- | --- |
| 生成中改条件 | 发 g1（version 5）；1 秒内 PATCH conditions → version 6；再发 g2（version 6） | g1 最终 status = superseded，GET /generations/g1 无 result；g2 = succeeded；GET /conversations/{cid} 的 active_generation_id = g2，status = draft_ready |
| 旧结果不覆盖 | 用 g1（superseded）调 POST /plans | 409 STALE_GENERATION；已存方案 version 与内容不变 |
| 重复保存 | 连续两次 POST /plans（同 conversation_id，同 generation_id） | 两次返回同一 plan_id；version 1 → 2；库中该对话只有一条 plan 记录 |
| 并发改条件 | 两个 PATCH conditions 同时带 expected_version = 5 | 一个 200（version 6），一个 409 VERSION_CONFLICT |
| 并发保存 | 两个 POST /plans 同时带 expected_version = 1 | 一个 200（version 2），一个 409 |
| 取消 | 发 g1 后调 POST /generations/g1/cancel | 200，status = superseded；之后 g1 的回包不改任何数据 |

**判据**：任何时序组合下，「已存方案」的内容只能由最新一轮且被成功保存的 generation 决定；被取代的结果既不能写入方案，也不能改写当前对话的 draft。
